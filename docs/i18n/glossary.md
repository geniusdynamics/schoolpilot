# Translation glossary

Status: **draft, not reviewed by a native speaker**. The Kiswahili column follows usage in Kenyan schools as far as
the author knows it; the French column aims at schools in francophone Africa and in France and avoids terms that
only one of the two uses where a neutral one exists. The Portuguese column aims at schools in Mozambique, Angola and
Portugal: it uses European orthography with the post-1990 Orthographic Agreement spellings (ativo, ação) that all three
countries now teach, and a neutral term where Portugal and the African countries differ. The Arabic column is Modern
Standard Arabic as found in school software, with no dialect words. Mark a row `reviewed` in the last column once a
native reviewer has confirmed it.

## Rules the locale files follow

- Every `{{placeholder}}` is kept exactly as in English; `src/i18n/completeness.ts` fails the build when one changes.
- Brand names (SchoolPilot) and acronyms (CSV, PDF, KCSE, CBE) stay in English.
- Labels for buttons are kept short; sentences keep the register of the English source.
- A string that is legitimately identical to English is listed with its reason in `src/i18n/untranslatable.ts`.
- French uses the typographic space before `:` and `?`/`!` only where the existing strings already did (the source
  catalogue is not consistent about it); this is left for the reviewer.
- Portuguese addresses the user with the formal third person ("Selecione", "Introduza", "Tente novamente") and uses
  "introduza" rather than the Brazilian "digite"; "utilizador" rather than "usuário".
- Arabic uses Western digits (0-9) in values, as `src/utils/locale` does for data fields. Example class names such as
  Form 1, Grade 7 and Year 8, route paths and the `bulk-streams` id stay in Latin script inside Arabic sentences.
- Arabic uses imperative forms for buttons ("حفظ", "إلغاء") and the masculine singular for second-person text, which is
  the convention of Arabic software.
