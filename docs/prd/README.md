## 1. Problem

SchoolPilot has broad module coverage but cannot run a real school: data is not persisted,
setup cannot complete, and core workflows (classes, terms, fees, billing, payments, marks,
attendance, admissions, promotion, report cards) are blocked or corrupt data (audit: 18 P0,
16 P1). The product also hard-codes Kenyan 8-4-4 assumptions while the market needs Kenya CBE
(incl. Junior and Senior School), British, and other African curricula, and it is about to be
open-sourced.

## 2. Goals and non-goals

### Goals (measurable)
| ID | Goal | Measure |
| --- | --- | --- |
| G1 | A new school can go from install to first term's invoices without support | ≤ 2 h, GP-1 green |
| G2 | No data loss, no fake data, no fail-open auth | Probe C01–C04 pass; zero incidents in pilots |
| G3 | Every golden-path workflow works end-to-end | GP-1…GP-8 green in CI |
| G4 | Curriculum-agnostic core; Kenya CBE, 8-4-4 (transition), British packs verified | Pack conformance vectors pass; pilot schools sign off |
| G5 | Finance a bursar trusts | Balances reconcile to the shilling; M-Pesa auto-match ≥ 95 % in pilot |
| G6 | Works offline and on several devices | GP-7 green; sync lag < 60 s on LAN |
| G7 | Ready for open-source contributors | Contract scan zero, typed data layer, docs, CI, licence, pack authoring guide |

### Non-goals (this PRD)
Library, inventory, nutrition and HR payroll **calculation** beyond the pack interface; LMS
content delivery; timetable auto-generation; native mobile apps (PWA only).

## 3. Users
Head teacher, deputy/director of studies, registrar, bursar/accounts clerk, class teacher,
subject teacher, exams officer, boarding staff, guardian, learner, system administrator,
proprietor/board (spec [README §4](../specs/multi-curriculum-platform/README.md#4-personas--primary-jobs)).

## 6. Definition of done

**Task:** acceptance criteria met; failing test written first (or waiver recorded); gate
`task` PASS; one commit on `consolidation` with the task id; ledger updated.
**Wave:** all wave tasks done or explicitly deferred; wave log written; pushed.
**Phase:** every task done/deferred-with-owner; gate `phase --probe` PASS; phase exit criteria
met; phase completion log written (`workflow-log/`); `PROGRESS.md` updated; baseline tightened.

## 7. Risks

| Risk | Impact | Mitigation |
| --- | --- | --- |
| Parallel agents edit the same files | Merge conflicts, regressions | Lane file-ownership per wave; worktrees; serial squash-integration with gate after each |
| Agents "pass" by weakening tests/ratchet | Silent quality loss | Gate compares to baseline; G6 forbids casts; verifier stage is adversarial; ratchet only tightens |
| Curriculum facts wrong or outdated | Wrong report cards | Packs carry sources + `verification` status; vectors from official examples; country maintainers |
| Migration of existing schools corrupts data | Trust loss | Pre-flight backup, id map, before/after balance checks, rollback (08 §5) |
| Sync engine choice wrong | Rework in P4 | Decision record DR-02 with spike before commitment |
| Mid-term upgrades disrupt schools | Operational harm | Release channels; schema changes only in holidays (08 §6) |
| Scope creep from 11 modules | Delay | Out-of-scope modules only receive P0 contract fixes until 1.0 |
