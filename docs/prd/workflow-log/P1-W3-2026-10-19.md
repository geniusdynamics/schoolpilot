### Review rounds (what they caught)

- **A04, round 1 → changes_required.** Two real DDL defects. (1) Canonical primary keys were nullable: SQLite's `TEXT PRIMARY KEY` does not imply `NOT NULL`, and a real NULL-id insert succeeded on all 63 tables. (2) The primary-key resolution silently changed 3 of 158 legacy collections — `app_settings` lost `NOT NULL` on id, `stock_levels`/`student_wallets` gained `PRIMARY KEY`. The fix gates the resolved-key behaviour on strict mode, emits `"id" TEXT NOT NULL PRIMARY KEY`, and pins the legacy path with a committed SHA-256 fixture over all 158 collections. Round 2: **approve**, independently re-proven (63/63 `id.notnull=1`, NULL-id inserts rejected, 158/158 legacy SQL identical, fixture hashes recomputed from the base).
- **B02, round 1 → changes_required.** Three findings. (1) **§12.7 was bypassable in two steps**: the posting freeze checked the previous status only and did not freeze `status` itself, so a posted invoice could be moved to `draft` and its total then rewritten to 1 cent (same for a payment). (2) The D02 form seam did not close: the form's whole-record payload is refused by the repository, and `RepositoryRow` merged `rowVersion` into the entity row, so a row read back failed its own entity schema. (3) The deferral table named the wrong owning task for all four deferred §12 parts. Fixes: freeze the `status` field and refuse a transition out of a frozen state; export `toWritableValues(row)` and document binding `createSchemaFor`/`updateSchemaFor` in the forms guide; correct the owners to P3-A02, P3-A03, P1-B03 and the spec-03 engine. The commander additionally required the freeze to be extended to posted **credit notes and refunds** rather than documenting the same hole as future work; a refund freezes at `approved` (its posting moment), keeping `requested` editable and `paid`/`rejected` reachable.
- **D02, round 1 → approve with findings.** The verifier proved the parity matrix (18/18 rendered-form cases matched `schema.safeParse`), money exactness, DST-safe dates in two time zones, phone/identifier behaviour and picker binding. A focused fix round then corrected the two substantive findings — money parsing rewrote malformed input (`1e3` → 13.00) and widget parse errors did not block submit — plus the dangling `aria-describedby`, boolean inference and optional-identifier clearing. That round was accepted on its committed tests and a direct diff review rather than a second independent verifier pass.

## Verifier notes (non-blocking)

**A04 — for B02/C migrations**
- Repositories must use `canonicalDatabaseSchema()` / `applyCanonicalSchema()`; `databaseSchemaFor()` does not set strict and is not equivalent.
- Foreign keys are enforced only when the adapter is opened with `foreignKeys: true`.
- Transactions are single-level: nested `transaction()` rejects and outer adapter calls inside a transaction reject.
- The adapter provides statements/transactions/error mapping only — typed row mapping, CRUD builders, watch events, `audit_event` + per-row `version` and statement caching were B02's.
- `applySchema` is `CREATE IF NOT EXISTS` only; no ALTER path (B02 adds its own idempotent ALTER for the concurrency column).
- Browser worker crash handling leaves a dead worker reference; browser OPFS behaviour is not in the committed CI suite. Production-built worker execution, cross-browser OPFS, multi-tab contention and quota behaviour remain unproven.
- The legacy fixture deliberately pins the pre-existing invalid `app_settings` index name; fixing it needs a deliberate re-baseline.

**B02 — for B03/B04/B05**
- The derived create/update schemas are shape-only (zod's `omit`/`partial` drop cross-field refinements); the repository re-validates the assembled row, so a refinement still rejects the write but surfaces from the repository rather than the form.
- A row read from the repository carries `rowVersion`; strip it with `toWritableValues(row)` before validating with the entity schema or submitting to `update`.
- An optional-but-not-nullable field cannot be cleared through `update` (only `.nullish()` fields can, with `null`); making such a field clearable needs `.nullish()` in the entity schema (A03's registry).
- JSON id lists (`fee_item_ids`, `level_ids`, …) carry no foreign key, so their entries are not resolved.
- The commit sequence is per repository instance and is allocated before the write, so a refused write consumes a number: B05 must treat it as an opaque monotonic token, never a commit count.
- Deferred: §12.7 journal-entry immutability (P3-A02), §12.9 sequence scope/never-reused (P3-A03, unique half enforced), §12.5's exception branch (spec-03 engine, needs a registry change), roles/permissions and the platform `audit_event` (P1-B03).

**D02 — for E01–E05**
- Pass the exact schema object the repository uses; seed system fields on create or share a create/update schema; declare metadata for every editable field (booleans need `widget: 'checkbox'`, phones need `country`/`dialCode`).
- Array fields need a repeater (only fixed indices render today); an invalid date silently reverts; form strings are inline English with keys recorded but not wired.
- i18n files: `docs/prd/workflow-log/pending-i18n/P1-D0{1,2}.json` and `P1-B02.json`.
