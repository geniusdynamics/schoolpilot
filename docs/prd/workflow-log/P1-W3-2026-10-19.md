### Review rounds (what they caught)

- **A04, round 1 → changes_required.** Two real DDL defects. (1) Canonical primary keys were nullable: SQLite's `TEXT PRIMARY KEY` does not imply `NOT NULL`, and a real NULL-id insert succeeded on all 63 tables. (2) The primary-key resolution silently changed 3 of 158 legacy collections — `app_settings` lost `NOT NULL` on id, `stock_levels`/`student_wallets` gained `PRIMARY KEY`. The fix gates the resolved-key behaviour on strict mode, emits `"id" TEXT NOT NULL PRIMARY KEY` for canonical tables, and pins the legacy path with a committed SHA-256 fixture over all 158 collections. Round 2: **approve**, independently re-proven (63/63 `id.notnull=1`, NULL-id inserts rejected, 158/158 legacy SQL identical, fixture hashes recomputed from the base).
- **D02, round 1 → approve with findings.** The verifier proved the parity matrix (18/18 rendered-form cases matched `schema.safeParse`), money exactness, DST-safe dates in two time zones, phone/identifier behaviour and picker binding. A focused fix round then corrected the two substantive findings — money parsing rewrote malformed input (`1e3` → 13.00) and widget parse errors did not block submit — plus the dangling `aria-describedby`, boolean inference and optional-identifier clearing. The fix round was accepted on its committed tests and a direct diff review, not a second independent verifier pass.

## Verifier notes (non-blocking)

**A04 — for B02/C migrations**
- Repositories must use `canonicalDatabaseSchema()` / `applyCanonicalSchema()`; `databaseSchemaFor()` does not set strict and must not be treated as equivalent.
- Foreign keys are enforced only when the adapter is opened with `foreignKeys: true`. B02's referential-integrity acceptance requires it.
- Transactions are single-level: nested `transaction()` rejects and outer adapter calls inside a transaction reject. B02 must thread the `SqliteTransaction` handle through repository methods or add savepoints later.
- The adapter provides statements/transactions/error mapping only. B02 still owns typed row encode/decode, per-table CRUD builders, watch/change events, `audit_event` + per-row `version`, and statement caching (no prepare API yet).
- `applySchema` is `CREATE IF NOT EXISTS` only — no ALTER/migration path for existing strict-less tables; C01–C05 must handle that explicitly.
- Browser worker crash handling leaves a dead worker reference (later calls can wait the 30 s timeout); browser OPFS worker behaviour is not in the committed CI suite. Production-built worker execution, cross-browser OPFS, multi-tab contention and quota behaviour remain unproven.
- `toDatabaseProperty` does not propagate a required `.nullable()` field's nullability; latent, no current field affected.
- The legacy fixture deliberately pins the pre-existing invalid `app_settings` index name; fixing it needs a deliberate re-baseline.

**D02 — for E01–E05**
- Pass the exact schema object the repository uses; seed system fields on create or share a create/update schema; declare metadata for every editable field (booleans require `widget: 'checkbox'`; phones require `country`/`dialCode`).
- Array fields need a repeater (only fixed indices render today); optional date input silently reverts invalid text; the form strings are inline English with keys recorded but not wired.
- i18n file: `docs/prd/workflow-log/pending-i18n/P1-D02.json` (`common.entityForm.*`), in addition to D01's picker keys.
