## The four fixes that came out of running the app, not the tests

The wave's tasks were green while the product still could not bill its own sample school. Each of these
was found by driving the UI or by a golden path, and each is committed with the regression that proves
it:

1. **The ledger was never opened** (`630c9b6`). The statements and accounting pages took a ledger as a
   prop and the shell handed them none, so the running app showed *"The ledger is not connected"*. The
   pages now fall back to `canonicalAdapter()`, and the finance golden path drives both and reads their
   own tie badges.
2. **One missing column took down every canonical page** (`b05821b`). `ensureConcurrencyColumns` became
   an additive sync: any column the registry declares and the table lacks is added on open. The
   regression test reproduces the owner's own `no such column: "level_id"` error.
3. **A wizard-created school had no identity** (`f195747`). The admin's canonical `user` row was never
   created and no staff row was linked, so marks, results, analysis, promotion, report publishing, the
   cashier and the workflow actor all reported "no staff record is linked". The wizard now creates the
   `user`, the staff row and the link in both directions; `src/data/canonicalIdentity.ts` resolves the
   session's canonical identity.
4. **The sample school could not be priced** (`81fa6cc`, `6806731`, `6583e4c`). Three separate faults
   stacked on one another, and each had to be fixed to see the next:
   - the seed's schedule declared no fee category and its lines named no residence, while its header
     spanned day and boarder — `resolveCell` refused with `cell_dimension_undeclared`;
   - the run's pre-filter rejected any learner whose enrolment names no fee category when the schedule
     declared one, even though the matrix resolves an omitted dimension the schedule is unambiguous
     about — and **nothing in the app gives a learner a fee category**, so every learner was refused;
   - once the filter passed, the matrix found no cell at all, because the seed's lines named no level
     while the header declared every level, so each line had no effective address.

   The seed now names the level, residence and category each line prices; the pre-filter defers an
   unnamed dimension to the matrix; and the seed test asserts what the fixes are for — a billing run
   over the seeded school reports no unresolved cell.

**Worth stating plainly:** defect 4's middle fault is the one that matters beyond the sample school.
A fee category exists so that a school can price day scholars differently from boarders, or citizens
differently from staff — and no screen in the product lets a registrar record which category a learner
is in. A schedule that declares two categories still refuses every learner, correctly but uselessly.
That is a product gap, not a test gap, and it is recorded below.

## The gate

- **CI is the authority for a diff this size.** The local gate's G3 batches `vitest related` because
  Windows caps a command line at ~8k characters; on Windows the batched run fails for reasons that are
  not the code. Four suites fail locally that pass on CI: two load-sensitive (`animations.test.tsx`,
  `AuthLoginRedirect.test.tsx`) and two gate-tooling tests that are Windows-only
  (`scripts/prd/fix-encoding.test.mjs`, `scripts/prd/__tests__/eslint-gate.test.ts`).
- The golden-path job runs GP-1-lite, GP-6 and the finance golden path on a real SQLite-WASM database.
  A golden-path failure is a product failure, and two of this wave's fixes came from exactly that.

## Known gaps carried out of these waves

- **The RBAC layer is built and wired into nothing.** `useRBAC` is called with no user id, so write
  controls never render for anyone; the repository is built with no authorize hook, so permissions are
  never consulted on a write; and no actor is passed, so audit rows carry a null actor. Found by P3-Q02's
  own review and left for P4-C02, which is where the server-side RBAC lands.
- **No fee category can be recorded on a learner** (above).
- **The report templates, the ranking policy and the observation pack still read a hardcoded bundled
  `ke-cbe` pack** rather than the installed programme's.
- The canonical `grading_scale` cannot store a band's upper-bound convention, so a school on a shipped
  pack cannot award a band.
- `invoice_line` cannot record the schedule version a bill was priced from.
- The wizard creates no staff (beyond the admin), teaching groups, assessments, learners, job titles,
  fee items or second academic year.
- **Six academics detail screens** are described as hub tabs by `pageRouteExemptions.ts` but no hub
  imports them and no route registers them, so they are unreachable by URL.
- Eight i18n descriptions resolve to placeholder strings (`"Description"`, `"List"`, `"Management
  Description"`); they are behind tooltips, not fixed.
