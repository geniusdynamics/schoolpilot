## Verifier notes (non-blocking)

- H03: `StudentWalletPage` computes `running_balance` from its own snapshot and the loading guard was removed, so posting before load can overwrite a balance; `useNutritionData.addMealConsumptionLog` treats any plan row as active and stores a positive amount for a DEBIT; Menus/Merchants/StudentMealAssignments leave rejections unhandled; the test insert returns a bare doc instead of `{ id, doc }`.
- H04: shared `Role.id`/`role_id` remain numeric and `SettingsUsersPage` still writes `Number(values.role_id)`; `UnifiedSettingsPage.handleUserSubmit` still does not write the role.
- H02: `FinesPage` sends `amount` while `fineSchema` expects `fine_amount`, so an added fine loses its amount under SQLite; `FinesPage` carries a TS2345 hidden by the ratchet; mutation errors are not surfaced.
- E04: `transportRoutesSchema` still declares `route_name`/`monthly_fee` while pages write `name`/`cost_per_period`, so the SQLite provider drops those fields; finance FK types remain numeric behind `as unknown as` casts; only GeneralReceipts has a failure-path test.
- F05: a forced page break after the last card can emit a blank page; print is enabled before results/attendance load; the attendance denominator is "days with records" rather than days open; the next-term lookup is not year-scoped; `marks_out_of || 100` treats 0 as 100.
- G08: `TabValidationService.validateTabRoute` still uses the shape-only predicate (the dormant legacy tabStore still accepts `/bulk-streams`); the route gate is root-level, so an unknown subpath under a real root can still become a tab; `APP_ROUTE_ROOTS` duplicates the module registry and can drift.
