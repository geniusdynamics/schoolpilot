## Findings worth carrying forward

1. **Six genuine defects, all proven by a golden path rather than asserted.** The largest: **no
   canonical `user` row was ever created**, so `report_card.published_by` and
   `promotion_decision.decided_by` were written with the legacy login id — a UUIDv4 where the
   canonical model demands UUIDv7 — and both report publishing and promotion commits failed schema
   validation **in a real browser while the phase's own harness passed against a fake store.** That
   is precisely the "the tests that mattered mocked the layer that was broken" failure mode spec 08
   §1 names, and it is the strongest argument yet for the golden paths existing.

   The others: the promotion page never received an approver so Approve was permanently disabled; it
   resolved pack rules from the wrong programme; the demo school's grading scale declared gapped
   ranges that the canonical half-open convention rejects, so no learner ever received a banded
   grade; the promotion service resolved a target level by code across the whole institution, so two
   programmes declaring F1–F4 made every promotion a conflict; and the student directory read only
   active enrolments, so a repeating learner showed no class.

2. **Four pages shipped built, tested, gated and unreachable.** Route registration lives outside a
   page's ownership, and a navigation entry is not a route — `DynamicRoutes` reads the module's
   separate `routes` array. This is now a guard, not a habit.

3. **The guard's first version was wrong, and the correction is the useful part.** It read only
   `routes`, so it flagged 30 pages that navigation already reached — false positives that would
   have taught everyone to add exemptions instead of fixing routes. Reachability is now a property
   of the declaration, not of a mode: a route names the page, or a non-deprecated navigation entry
   carries its `page`. That makes it correct for both shapes this system supports — hub-and-spoke,
   and direct page links with no hub. Registry: 165 entries (132 deprecated redirects, 22 hub tabs,
   33 legacy pages), ratcheted so it can only shrink.

4. **The wave gate's G3 flake is load, not regression.** It failed once with an unhandled
   `window is not defined` rejection; the identical selection passed twice afterwards (506/506), and
   P3-A01 independently hit the same load flake in a different suite. Recorded rather than chased.

## Known gaps carried out of this wave

- **The canonical `grading_scale` cannot store a band's upper-bound convention or input source.**
  Every shipped pack declares inclusive whole-mark ranges, which project to gapped half-open bands,
  so `prepareGradingScale` refuses them — **a school on `ke-844` or `ke-cbe` cannot award a band in
  the results or report path.** Only the demo school's own scale was repaired, so the golden paths
  could prove the banded path at all. This needs a schema addition or a normalising pack install.
- A mark of exactly 100 falls outside every band of a canonically stored scale.
- Observations → term judgement has no reachable path: no page creates canonical `outcome` rows.
- Per-group assessment workflow and moderation history still have no canonical entity; E01 keeps them
  in a durable browser store, and the new workflow-engine mission (dispatched separately) is where
  that should be absorbed.
- The pack registry is now wired into the wizard, but E01 still resolves schemes from
  `assessment_scheme` rows and E03 takes aggregation definitions as a prop.
