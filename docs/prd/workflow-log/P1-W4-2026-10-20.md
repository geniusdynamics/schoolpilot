### Review rounds (what they caught — every one of these was invisible to the gate)

- **B03: five blocking holes, with the gate green throughout.** The 29 committed tests only covered the create path. A disabled account with a role but no active user row listed every row in the database, including another institution's (the empty scope meant "no filter"); the mark list was wider than the mark row check, so a teacher read another subject teacher's marks through `list` while `get` refused the same row; `update` judged only the merged row, so a teacher rewrote another group's mark and moved it into their own group; `auditLog()` without an entity returned the whole database with full before/after payloads; and `learner.medical.read` was a fiction — a teacher who did not hold it still received allergies, conditions and medications. The fix added an invariant test that the list set equals the get set for every entity, which immediately caught a second disagreement (the `institution` row is judged by an `institution_id` column it does not have).
- **B05: a 1 Hz resubscribe loop** that contradicted the module's own README, plus a derived-map leak (6 → 46 entries over 20 renders, each holding a full `byId` map), plus a **masked success** where a write that never reached the repository was reported `observed: true`. About 60 lines of speculative machinery were deleted.
- **A05: a data-loss path.** `restoreDatabase` dropped every table outside a transaction and replayed the dump outside a transaction, so a restore that failed left the database **empty** — proven: `["gadget","keep"]` → error → `[]` → the row gone. The trigger was a malformed dump for any `CREATE` carrying a SQL comment. Both are fixed, and the dump now validates itself before it is handed out.
- **C06: the repair tool could create the corruption it exists to repair.** A `set_reference` fix could write an enrolment whose class group was of another level or year — the exact §12.2 violation the repository refuses — and it could point a live row at an **archived** class group, or enrol a learner into one. The tool now refuses both, and lists the choices that cannot be taken with the reason.
- **C01: a fixture that hid a real branch, and a document that promised more than the code did.** The fixture omitted the `dormitories` table, so the test asserted a boarding policy no real installation produces; and the contract document claimed every platform default was recorded as an assumption when, with a faithful database, the list was empty.
- **A03a: a register could exist only once per scope per day**, which made the spec's own `period_n` kind unusable.

## Handoffs for W5

- **The repository is the only way in.** `createRepository` + `ScopedRepository` + the B05 hooks + D02's `SchemaEntityForm` + D01's `EntityPicker`. The E-lane tasks must use the entity's own schema object — the same one the repository validates with — not a copy.
- **`toWritableValues(row)`** before validating a repository row with the entity schema (the row carries `rowVersion`) or submitting it to `update`; `expectedVersion` is mandatory on `update`.
- **The commit sequence is an opaque token**, allocated before the write (a refused write consumes a number), comparable only inside one repository instance. The cache rejects a payload below its committed sequence.
- **The watch delivery shows committed state** — a watcher never sees the rows of a transaction that a later failure rolls back.
- **The canonical repository provider is not yet a shared app-level seam.** E05 had to carry one copy per module because the module lane forbids a shared file; the W5 integration extracts one.
- **The canonical model does not cover** inventory stock, loans, meals, payroll, the finance ledger or student categories. E05 marks those call sites `GAP(P1-E05)` with the missing entity named; a registry follow-up owns the rest. Two columns of the student masterlist (Category, Dormitory) now render empty for this reason and are on the record.

## CI and tooling reliability

- **The gate could report success without testing anything.** `git rev-parse` echoes an argument it cannot resolve, so an unresolvable `--base` produced an empty diff, G3/G4/G7 skipped and GATE PASSED — two implementers hit it in one wave, each by my own typo in a brief. The gate now verifies the base with `git cat-file -e <sha>^{commit}` and fails loudly, and it refuses to report success over an empty diff (`--allow-empty` is the explicit opt-out).
- **pnpm 10 blocks dependency build scripts by default**, so `better-sqlite3`'s native binding was never produced on CI and A04's node-driver tests failed (12 tests, "Could not locate the bindings file"). Fixed by approving the build; the lockfile stays in sync.
- **The load-sensitive live-refresh flake is fixed** rather than listed as a known failure: the test now waits for the read count to settle and for the watch subscription, and a timeout still fails the test. The baseline file was proven flaky (1/8 sequential, 1/4 concurrent); the new one is 8/8 and 4/4 under load.
- `scripts/prd/__tests__/eslint-gate.test.ts` fails on Windows (it spawns `npx` without `shell: true`); it is pre-existing and fails identically on the base commit.
