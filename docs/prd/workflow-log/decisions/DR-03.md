# DR-03 — Licence: Apache-2.0 for the code, CC-BY-4.0 for pack data

**Date:** 2026-10-28
**Status:** accepted
**Decided by:** the repository owner (Genius Dynamics); recorded by implementer P6-E01
**Supersedes:** nothing. Realises spec 08 §7 ("Licence: choose and document ... packs under a permissive data licence (CC-BY-4.0) with source citations").

## Context

P6 takes the repository public and ships packs to schools and integrators, and spec 08 §7 requires a documented licence choice before publication. Until this record the root `README.md` called the project proprietary, and there was no `LICENSE` or `NOTICE` file at the repository root.

Two kinds of work live in this repository and they do not need the same licence:

- **the application code** (`src/`, `server/`, `scripts/`, tooling) — software;
- **the curriculum, country and payroll packs** under `packs/**` — data: syllabi, subject and grade structures, assessment vectors, country metadata and payroll rule tables.

Each pack's `README.md` already cites the official sources it was derived from and records its `verification` status. Those citations are the attribution the pack licence relies on, so they stay with the packs.

The choice affects three things that matter to this project:

1. **Adoption** — whether a school, ministry, NGO or integrator can use the software without a procurement review turning into a legal review.
2. **Hosted forks** — whether a company can run the software as a service and keep its modifications closed.
3. **Procurement** — whether the licence is on buyers' approved lists and whether an explicit patent grant protects a school that is deploying the software.

## Options

### Code

#### A. AGPL-3.0

Strong copyleft that reaches network use: anyone offering a modified version as a hosted service must offer the corresponding source. The upside is direct: improvements to a hosted service come back, and no competitor can take the code closed. The cost is the reason it is not chosen here. Copyleft is rejected outright by a number of procurement checklists and school IT policies, it puts an obligation on a school that customises and hosts internally, and it protects against a business model (a competing closed hosted service) that does not exist yet while raising the barrier for the audience the project is trying to reach. It stays on the table for a future major version if that fork materialises.

#### B. Apache-2.0 — chosen

Permissive, with three things MIT does not have: an explicit patent grant and a patent-termination clause (§3), a NOTICE-retention requirement for redistributions (§4(d)), and a trademark carve-out (§6). It lets a vendor, a ministry or an integrator build on the code and keep its own changes closed, which is what most procurement processes and integrators expect; it is compatible with the permissive licences (MIT, BSD, Apache-2.0) that dominate the JavaScript ecosystem, so it does not poison the dependency graph.

What is accepted with it: a competitor may host a modified version without publishing its changes, and the grant cannot be withdrawn for what has been published. The patent grant and the NOTICE mechanism are worth more to a school buying software than control over a hosted service the project does not yet run.

#### C. MIT

The shortest permissive licence and the easiest to read and comply with. But it carries no express patent grant — the single most valuable clause for public-sector procurement — no NOTICE mechanism to carry attribution, and no statement about trademarks. It gives away the same hosted-fork exposure as Apache-2.0 without the protection that compensates for it. Rejected.

### Pack data

#### D. CC-BY-4.0 — chosen

Allows sharing, adaptation and commercial use with attribution and no share-alike. A school, ministry or NGO can localise a pack, keep the adaptation internal or publish it under terms of its own; the only obligation is attribution, and the per-pack source citations already provide it. This is exactly what spec 08 §7 asks for.

#### E. CC-BY-SA-4.0

The same permissions plus share-alike: adaptations must be distributed under the same licence. It keeps community pack improvements open, but it reaches a school's own localisation, and it conflicts with a ministry that wants to publish adapted curriculum under its own terms or mix it with material under another licence. Rejected for the same adoption reason as AGPL for the code. Pack data is also where a school's own work is most likely to end up, so a share-alike obligation there is felt most.

## Decision

- **Code: Apache License 2.0** (`LICENSE`, `NOTICE`, `package.json` `"license"`).
- **Pack data: Creative Commons Attribution 4.0 International** (`packs/LICENSE`), covering the curriculum, country and payroll packs under `packs/**`, including the locale and vector data they ship.
- The code that loads packs stays Apache-2.0. A single repository, two licences, each part keeps its own.

Rationale: adoption by schools, integrators and public procurement, plus an explicit patent grant, outweigh shielding a future hosted service. AGPL remains an option for a future major version.

The copyright holder is the repository owner, **Genius Dynamics** — the `geniusdynamics` organisation in the repository remote and the owner named in `docs/prd/README.md` — and the copyright line is 2026, the year of the public release this record accompanies. The repository's earliest commit is 2025-06-29, so a redistribution that carries pre-2026 history may state the earlier year as well.

## Consequences

### What a redistributor must do

Code (Apache-2.0):

- ship a copy of `LICENSE` with the code (§4(a));
- retain `NOTICE` and the attribution notices it carries (§4(d)), and retain copyright, patent, trademark and attribution notices from modified files (§4(c));
- mark modified files as changed (§4(b));
- not use the SchoolPilot name or logo beyond customary, reasonable use in describing the origin of the work (§6);
- accept that a patent suit alleging the work infringes terminates the patent grant (§3).

Pack data (CC-BY-4.0):

- give appropriate credit, link to the licence, and state whether changes were made;
- keep each pack's `README.md` source citations with the data and with any adaptation;
- note that adaptations may be released under other terms, because CC-BY-4.0 has no share-alike.

### Project consequences

- **Licence changes only in a major version.** Apache-2.0 and CC-BY-4.0 grants are irrevocable for what has been published. Changing the project's outbound licence applies to new releases only, needs the agreement of the copyright holder and of contributors whose work is included (the project has no CLA, so inbound contributions are licensed under Apache-2.0 §5 by default), and is therefore a major-version decision, announced and documented like this one.
- **AGPL is the named alternative** if a closed hosted fork becomes a real problem; that is a future major version, not a change to this one.
- **Dependencies were not audited.** This record chooses the project's outbound licence; it is not a dependency-licence audit, and none was performed in P6-E01.
- **No SPDX/REUSE headers were added** across the source tree. That is a large mechanical diff and is deliberately deferred rather than smuggled into a licence-decision task; it belongs in a later hygiene task.
- **Contributor documentation** (P6-E03) should point at `LICENSE`, `NOTICE` and `packs/LICENSE` rather than restate them.
- This record is engineering rationale, not legal advice; no external counsel has reviewed it.
