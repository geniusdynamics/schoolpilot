**Student Financial Overview Dashboard**
I. Core Objective
The primary goal is to design a comprehensive Student Financial Overview dashboard. This interface will serve as the central source of truth for an administrator to view and understand a single student's complete financial history. It must clearly present the student's current balance, a detailed breakdown of all charges (invoices), and a complete log of all payments made. The design must be clean, intuitive, and focused on providing actionable financial insights at a glance.
II. Dynamic Interaction & Workflow
The component is initiated by an administrator's action and must be data-driven.
Student Selection: An administrator selects a student from a list, search result, or another part of the system.
Dynamic Data Population: Upon selection, an API call is triggered to fetch the student's entire financial record. The dashboard populates with this specific data.
State Management:
Loading State: Implement clear loading indicators (e.g., shimmer effects or spinners) on all data-dependent components while the financial record is being fetched.
Empty State: If a student has no financial history, the dashboard should display a clear, user-friendly message like "No Financial Records Found for This Student." Individual sections (like "Payment History") should show similar messages if they are empty.
III. Layout & Structure
The overview should be structured using a two-column layout to separate high-level summary information from detailed historical data.
Page Header:
Title: A prominent H1 title: "Student Financial Overview".
Breadcrumbs: Clear navigational context, e.g., Dashboard > Students > [Student Name] > Financials.
Primary Actions: A set of key action buttons on the top-right:
Collect Fee: (with a dollar/credit-card icon) This button would open a separate modal or navigate to the dedicated fee collection page.
Export Summary: (with a download icon) To download a PDF report of the student's financial summary.
Main Content Layout (Two Columns):
Left Column (Summary & Status): A narrower, fixed-width column for at-a-glance identification and a high-level financial summary.
Right Column (Detailed History): A wider, main content column that uses a tabbed interface to provide a detailed, organized breakdown of all financial activities.
IV. Detailed Component Breakdown
A. Left Column Components
1. Student Profile Card:
Purpose: To clearly identify the student whose record is being viewed.
Components:
Student Avatar: Large, clear profile picture.
Student Name: Full name in a bold, prominent font.
Student ID & Class: Clearly labeled identifiers (e.g., "ID: ST-0dff65 | Class: Grade 10 - B").
2. Financial Summary Card:
Purpose: To provide an immediate, high-level overview of the student's financial standing.
Key Metrics (visualized with clear labels and large fonts):
Current Balance: The most prominent metric on the page. Displayed with color-coding (e.g., green for a zero or credit balance, red for a debit/due balance).
Total Fees: The cumulative sum of all invoices/charges.
Total Paid: The cumulative sum of all payments received.
Total Discount: The total amount of discounts applied.
Total Fine: The total amount of late fees accrued.
B. Right Column Components (Tabbed Interface)
Tab Navigator: A simple and clean navigation bar with the following tabs: "Invoices & Charges" and "Payment History".
Tab 1: "Invoices & Charges" (Default View)
Purpose: To provide a detailed, itemized list of every charge levied against the student.
Section Title: "All Invoices & Charges".
Data Table: A responsive table with the following columns:
Invoice ID: A unique, clickable identifier for each charge.
Fee Type/Description: (e.g., "Tuition Fee - June", "Annual Sports Fee", "Damaged Book Fine").
Due Date: The date the payment was due.
Amount: The total amount for that specific charge.
Status: A color-coded tag for clarity (e.g., Paid in green, Unpaid in orange, Overdue in red).
Action: A "View" icon/button to see the full details of that specific invoice.
Tab 2: "Payment History"
Purpose: To provide a chronological log of every payment received from the student.
Section Title: "All Received Payments".
Data Table: A responsive table with the following columns:
Transaction ID: The unique ID for the payment.
Payment Date: The date the payment was recorded.
Amount Paid: The value of the transaction.
Payment Method: (e.g., "Cash", "Card", "Bank Transfer").
Notes: Any administrative notes related to the payment.
