# Page Consolidation Plan v3 — Hub-and-Spoke with Dual Navigation (Guardrailed)

## Context

The `consolidation` branch contains a partially-implemented page consolidation that deviates significantly from the specification in `page-consolidation-plan-v2-637146.md`. Key problems identified:

- **38 hub pages created** but navigation registry still points to old standalone pages
- **Zero `deprecated: true` flags** set on old nav items; legacy redirect system redirects ALL deprecated routes to `/settings/data-management`
- **Duplicate route paths** in navigation (e.g., `/administration/certificates` registered twice, `/academics/assignments` registered twice)
- **ExamHubPage over-consolidates** 7 unrelated tabs at `/academics/exams` instead of the plan's separate hubs
- **36 of 38 hub pages use hardcoded mock data** instead of `useAppData()`
- **FilterBar prop mismatch** — hub pages pass `key`/`type` but component expects `id`/`options`
- **Dashboard quick-nav points to non-existent routes**
- **Module `routes` arrays at wrong level** — router reads `metadata.provides?.routes` but modules define `routes` at root

**New architectural decision**: Instead of reverting and rebuilding standalone hub pages with inline mock data, implement a **hub-and-spoke model** where:
1. **All existing standalone pages are preserved** and continue to work independently
2. **Hub pages are created as thin wrappers** that render existing pages as tab content via component imports
3. **Dual navigation**: Fullwidth mode shows all individual page links (navigating to hub + specific tab); Standard mode shows only hub page links

This approach preserves existing page investments, enables independent page improvement, and provides both granular and consolidated navigation experiences.

---

## Guardrails & Constraints

1. **Proof-of-concept first**: Start with Administration module only. Do NOT touch other modules until Admin pattern is validated.
2. **No nav item duplication**: Each nav item appears exactly once. Mode visibility is controlled by a `showInModes` property, not by duplicate entries.
3. **Shared redirect constant map**: All redirects live in one file. No hardcoded redirect strings scattered across module definitions.
4. **No cross-module redirects in nav**: Cross-module redirects (e.g., `/hr/staff-bio-data` → `/administration/staff?tab=bio-data`) are handled at the route level, not in module navigation arrays.
5. **TDD for foundation**: Write tests for `useSecondarySidebar` filtering and `generateDeprecatedRouteRedirects` BEFORE touching implementation.
6. **Content extraction is opt-out, not mandatory**: If a page has unique layout concerns that can't be extracted cleanly, leave it standalone and link it from the hub.
7. **Horizontal tabs, not vertical**: Use `TabNavigation` in `default` or `pills` variant at the top of the hub page. No sidebar tab layout needed.
8. **Budget 3x estimated effort**: Account for testing, edge cases, review cycles, and build fixes.

#### 2c. Fix Redirect Logic

**File: `src/routing/moduleRoutes.tsx`**

Replace hardcoded redirect with lookup from `redirectMap.ts`:

```typescript
import { getRedirectForRoute } from './redirectMap';

const generateDeprecatedRouteRedirects = (): React.ReactElement[] => {
  const deprecatedRoutes: React.ReactElement[] = [];
  const enabledModuleIds = moduleRegistry.getEnabledModules();

  enabledModuleIds.forEach(moduleId => {
    if (!moduleId) return;
    const metadata = moduleRegistry.getMetadata(moduleId);
    if (metadata?.navigation) {
      metadata.navigation.forEach((navItem: any) => {
        if (navItem?.deprecated && navItem?.path) {
          const redirectTo = navItem.redirectTo || getRedirectForRoute(navItem.path);
          if (redirectTo) {
            deprecatedRoutes.push(
              <Route
                key={navItem.path}
                path={navItem.path}
                element={<Navigate to={redirectTo} replace />}
              />
            );
          }
        }
      });
    }
  });

  // Also register cross-module redirects from redirectMap
  Object.entries(DEPRECATED_ROUTE_REDIRECTS).forEach(([path, redirectTo]) => {
    // Only add if not already covered by module nav items
    const alreadyCovered = deprecatedRoutes.some(r => r.key === path);
    if (!alreadyCovered) {
      deprecatedRoutes.push(
        <Route
          key={path}
          path={path}
          element={<Navigate to={redirectTo} replace />}
        />
      );
    }
  });

  return deprecatedRoutes;
};
```

#### 2e. Mode Filtering in Sidebar

**File: `src/hooks/useSecondarySidebar.ts`**

```typescript
import { useFullWidth } from '@/contexts/FullWidthContext';

const subMenus = useMemo(() => {
  let items = [];
  if (propItems && Array.isArray(propItems) && propItems.length > 0) {
    items = propItems.filter((item: any) => item != null);
  } else if (selectedModule?.children && Array.isArray(selectedModule.children)) {
    items = selectedModule.children.filter((item: any) => item != null);
  }
  if (selectedModuleId === 'dashboard') return [];

  const { isFullWidth } = useFullWidth();
  const currentMode = isFullWidth ? 'fullwidth' : 'standard';

  items = items.filter((item: any) => {
    // Deprecated items never show in sidebar
    if (item.deprecated) return false;
    // If no showInModes specified, default to standard-only visibility
    if (!item.showInModes) return currentMode === 'standard';
    return item.showInModes.includes(currentMode);
  });

  return items;
}, [selectedModule, propItems, selectedModuleId, favorites, isFullWidth]);
```

**Note:** `useFullWidth()` must be called at the top of the hook function, not inside `useMemo`. The `isFullWidth` value should be added to the dependency array.

#### 4b. Create Hub Page

**New file: `src/modules/administration/pages/SchoolConfigurationPage.tsx`**

```typescript
// ABOUTME: Hub page consolidating school configuration pages into tabbed interface
// ABOUTME: Wraps existing standalone pages as tabs using their *Content exports

import React from 'react';
import { useSearchParams } from 'react-router-dom';
import { TabNavigation } from '@/components/ui/TabNavigation';
import { BuildingOffice2Icon, IdentificationIcon, HomeIcon, TagIcon, UserGroupIcon, HandshakeIcon } from '@heroicons/react/24/outline';
import { DepartmentsContent } from './DepartmentsPage';
import { DesignationsContent } from './DesignationsPage';
import { DormitoriesContent } from './DormitoriesPage';
import { StudentCategoriesContent } from './StudentCategoriesPage';
import { ClubsContent } from './ClubsPage';
import { PartnersContent } from './PartnersPage';

const tabs = [
  { id: 'departments', label: 'Departments', icon: <BuildingOffice2Icon className="h-4 w-4" /> },
  { id: 'designations', label: 'Designations', icon: <IdentificationIcon className="h-4 w-4" /> },
  { id: 'dormitories', label: 'Dormitories', icon: <HomeIcon className="h-4 w-4" /> },
  { id: 'categories', label: 'Categories', icon: <TagIcon className="h-4 w-4" /> },
  { id: 'clubs', label: 'Clubs', icon: <UserGroupIcon className="h-4 w-4" /> },
  { id: 'partners', label: 'Partners', icon: <HandshakeIcon className="h-4 w-4" /> },
];

const SchoolConfigurationPage: React.FC = () => {
  const [searchParams, setSearchParams] = useSearchParams();
  const activeTab = searchParams.get('tab') || 'departments';

  const handleTabChange = (tabId: string) => {
    setSearchParams({ tab: tabId });
  };

  const renderTabContent = () => {
    switch (activeTab) {
      case 'departments': return <DepartmentsContent />;
      case 'designations': return <DesignationsContent />;
      case 'dormitories': return <DormitoriesContent />;
      case 'categories': return <StudentCategoriesContent />;
      case 'clubs': return <ClubsContent />;
      case 'partners': return <PartnersContent />;
      default: return <DepartmentsContent />;
    }
  };

  return (
    <div className="space-y-6">
      <TabNavigation
        tabs={tabs}
        activeTabId={activeTab}
        onTabChange={handleTabChange}
        variant="default"
      />
      <div className="px-2">
        {renderTabContent()}
      </div>
    </div>
  );
};

export default SchoolConfigurationPage;
```

## Rollback Strategy

If fullwidth mode breaks navigation:
1. Users can toggle fullwidth off via the existing layout toggle (persisted to localStorage)
2. Standard mode is the default and most stable path
3. The `showInModes` filtering has a safe default: items without `showInModes` appear in standard mode only
4. To emergency-disable: remove `showInModes: ['fullwidth']` from standalone items — they simply won't appear in fullwidth mode, but standard mode continues working
